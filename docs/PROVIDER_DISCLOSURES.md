# AI backend and narration disclosures

This document summarizes the versioned disclosures represented in Code Atlas source. It is not a live price, quota, eligibility, retention, or billing check. Direct text APIs, the initial Codex account route, local Pocket narration and optional Gemini speech have separate contracts. October 16 automated and native evidence is recorded in [Codex validation](acceptance/2026-10-16-codex-validation.md); remaining operation and release acceptance is separate.

## Direct text API providers

The versioned Gemini, OpenAI, and Anthropic records are defined in `src-tauri/src/provider.rs`. The selected provider and model are explicit; this direct API route does not discover models or switch providers after failure. Prices, model IDs, and provider terms are static release metadata checked on 13 October 2026 and must be verified against the linked first-party sources before release. The app cannot inspect the account, key tier, billing, quota, retention configuration, eligibility, or regional availability behind a user-supplied key.

### Data use and eligibility notices

- **Gemini API:** the app warns that Google may use content sent through unpaid Gemini API services to improve products and may have people review it. Google's terms have a paid-service data-use exception for users in the EEA, Switzerland, and the United Kingdom, including users of unpaid quota. Age, professional/business-use, supported-region, and account terms still apply.
- **OpenAI API:** the app discloses that API data is not used for training by default, while abuse-monitoring logs can contain prompts and responses and are normally retained for up to 30 days, subject to current account, legal, and safety controls. The reviewed Responses request sets `store: false`; this avoids Responses application-state storage and does not establish zero retention for all processing.
- **Anthropic API:** the app's structured-output Messages request uses the provider's schema feature. Its notice describes the documented Zero Data Retention qualification for that feature, including schema caching for up to 24 hours and applicable account, trust-and-safety, and legal exceptions. Verify current retention terms and account eligibility before sending source.

Each provider has a separate price, terms, supported-region, and API-key reference in the app. A listed price or a model's feature flag is not a live availability, account-eligibility, free-use, or per-operation capability check.

### Key handling and request boundary

The key is saved in a provider-specific macOS Keychain item and is never returned to the WebView. Rust loads it only after request review and explicit consent, keeps it in a zeroizing wrapper, and sends it in a sensitive HTTPS authentication header: `x-goog-api-key` for Gemini, `Authorization: Bearer` for OpenAI, and `x-api-key` for Anthropic. Keys are not included in the JSON request, request preview, local repository data, exports, or application-authored logs.

The current shared API route uses pinned `rig-core` 0.44.0 provider wires and a narrow Reqwest transport wrapper. Immediately before sending, the wrapper checks that the method, endpoint, JSON body, content type, and provider credential placeholder match the reviewed request. It requires HTTPS, applies a 90-second timeout, and bounds response bodies. The current app transport is unary; streaming is disabled even where a provider model supports streaming.

The user must explicitly choose a provider and model, inspect the request purpose, exact selected source/diff, prompt/settings, endpoint, body digest, cost uncertainty, and disclosure, and confirm the unchecked privacy, billing, and age/region/use controls. Opening settings, loading the catalog, saving a key, and building or rebuilding a request preview do not contact a model API. A request review is fingerprinted, expires after fifteen minutes, and can be consumed once. No provider/model fallback or automatic retry occurs.

### Current operation coverage

The shared route is connected to file chapters, one-section regeneration, PR Guides, a transient single-hunk PR change explanation, and a distinct transient Code Lens range-explanation operation. Existing repository-overview requests may be reopened through operation recovery, but the current UI does not offer new overview requests. Mock-dispatch fixtures cover each wired operation/provider pair, including consent, changed-review rejection, and no fallback after a synthetic quota failure. They also verify that accepted chapter history is byte-for-byte unchanged when a saved-operation request fails; transient PR change failures leave Git refs, the Git index, and PR Guide history unchanged. Separate loopback Reqwest/Rig tests verify reviewed-body and credential placement for each provider and that cancellation closes a pending local socket. The full t28 acceptance contract remains open for live vendor behavior and eligibility, production TLS/proxy behavior, provider-response parsing, and whether a provider accepted a request before local cancellation. See the [capability matrix](research/ai-backend-capability-matrix.md) for the current evidence. Returned chapters and PR Guides remain unaccepted until the local validation and user-review flows complete; Code Lens and PR change explanations are citation-validated transient results and are not persisted as drafts.

For a file chapter, the reviewed request contains the target file and up to eleven selected supporting files from the same immutable snapshot. Selected source is capped at 250 KB and the encoded request body at 512 KB; secret-like, binary, invalid-encoding, skipped, and uncaptured files are rejected. A PR Guide has a separate review based on two local Git refs resolved to immutable commits and up to twelve selected bounded text-diff files. Its fingerprint covers the selected diff evidence and changing the refs or selection invalidates consent.

Cancellation drops the in-flight local request future when the user cancels. The provider may already have received or started processing the request, so cancellation cannot promise a refund, erase transmitted content, or revoke provider work. Any late response is discarded or kept only as an unaccepted draft according to the operation's recovery path.

## Initial Codex account route

The Codex app-server integration uses a Rust-managed stdio child and the installed runtime’s existing ChatGPT account. With Codex selected, the header discovers the desktop executable, silently restores its existing account at app startup and loads model metadata. Future requests reuse the connection, model and reasoning, including after app restart. Restoration cannot start OAuth or open a browser; when sign-in is required, an explicit Connect action delegates browser sign-in and credential storage to Codex. Code Atlas does not read/copy authentication files, ask for an API key or change the user’s configuration. Disconnect stops this app’s connection and persists a pause in automatic reuse until the user selects Connect again, without logging out other Codex clients. This is the installed runtime’s login, not a Code Atlas implementation of direct Sign in with ChatGPT registration, PKCE or token sharing. Distribution eligibility and supported packaged runtime inventory remain release work.

App startup with Codex selected, Connect and model refresh can start Codex and contact its account services without sending repository context. The explicit `model/list` response supplies runtime model/reasoning choices, not proof of account entitlement, pricing or quota. Account/subscription usage and data terms are distinct from the direct OpenAI API notice above; the app does not promise free usage or remaining plan capacity. The reviewed operation can involve runtime-managed model calls, so the app does not claim an exact downstream request count or byte-for-byte vendor HTTP payload.

### Workspace investigation

The pinned workspace composer starts one ephemeral investigation through the existing Codex runtime, using GPT-6 Luna/max. Its initial app-authored contract is at most 32,000 encoded bytes and contains the question, bounded prior intent, output schema, instructions and optional captured starting references. It contains no whole-file source bundle or repository-wide index dump. Codex chooses what to inspect through five owned search, read, definition, relationship and module tools. A sixth owned tool, `propose_answer_section`, publishes locally validated unaccepted draft sections without gaining source access or changing repository files. Six unique sections and eight proposal attempts share the original operation budget. Search results expose range metadata; implementation text is supplied only through range reads. The runtime can make multiple model calls and consume account quota during this investigation.

The first request needs a versioned snapshot-sharing permission bound to the manifest, observed account and executable. That permission permits automatic selection of up to 12 captured files and 250,000 distinct source bytes across the operation; each requested range is at most 32,768 bytes. Shared metadata is separately capped at 256,000 bytes, native JSON tool payloads at 1,000,000 bytes, one result at 128,000 bytes, and calls at 64 under a ten-minute deadline. These are app-authored payload measurements, not tokens or exact downstream HTTP framing. Overlapping code is sent once. Invalid read bounds return charged metadata with no code, allowing the agent to correct its request. Native scope, exclusion, captured hash, runtime/account observation, revocation and cancellation checks run before delivery. Local full-file verification and citation validation do not transmit those full files.

Old whole-file permissions cannot silently enable tool access. A new policy requires one new sharing decision; routine tools need no separate dialog. Shell, web, live-checkout access, delegation and unrelated inherited MCP tools stay disabled. The local MCP helper uses standard stdio and a private Unix socket; it adds no Node server or listening TCP port. The app persists range/call identities and accounting without source text or model reasoning in the evidence ledger. Progressive section chapters carry a schema-5 generation origin linking an immutable delivered-prefix checkpoint to the request and admitted ranges. Earlier origin/ledger versions remain readable. The bounded local answer record also retains exact structured proposals and final manifests, including rejected attempts, and native validation findings; it is not sent as a source bundle. This is local lineage, not an account attestation or a guarantee of explanation quality.

There is no automatic inference resubmission or identifier-correction turn in this workspace route. The agent's own search/refinement/read decisions are steps within the original operation and budget. Transport uncertainty, scope changes, Stop or deadline failure prevent later publication; earlier durably validated sections remain readable. A final manifest must name the latest published sections and cannot replace them. Later rejection/failure produces a partial or stopped answer rather than removing those sections. Cancellation cannot retract data already delivered or refund provider work. The app does not resume inference after restart. Local recovery never reconnects or replays AI. Guide lifetime allowances, standalone answers, and historical receipts share a limit of 1,000 answer-record slots; each record is capped at 4 MiB. Capacity checks preserve existing work and refuse a new investigation before exceeding the limit. The store has no separate aggregate byte quota, so its theoretical record ceiling is about 4 GiB, plus filesystem overhead. User-managed receipt removal is explicit and never automatic. Publication never starts narration synthesis/playback. Installed runtime/package, meaning and timing acceptance remains open; see [progressive answer sections](kata-tasks/73-progressive-answer-sections.md).

### Other Codex operations

Existing file-chapter, overview-recovery, section-repair, Code Lens, Git-explanation and reading-plan requests keep their exact request-review contracts. Those dialogs review immutable source, prompt/schema, model/reasoning and fixed approval policy before explicit sharing. A batch review covers its exact remaining chapter requests. Each request is rebuilt and compared before dispatch; changed identity/source/settings stop the queue. Recovered overview contracts may contain their previously reviewed one-attempt identifier-alignment policy. They do not gain the new tool scope. Results remain unaccepted pending local validation and user review. There is no direct API fallback. Runtime/account refresh, filesystem/process/egress and packaged qualification remain outstanding.

Section regeneration, Code Lens, PR Guide, PR change and bounded planning have Codex source dispatch. The dated acceptance record distinguishes executed file generation from those remaining operation gates. Claude Agent is deferred; Gemini CLI and Antigravity remain separate candidates. See [the dated backend evaluation](research/2026-10-15-agent-backends.md) and [Codex task](kata-tasks/40-codex-account-backend.md) for remaining qualification.

## Optional section narration

### Local Pocket TTS default

The global **Connections → Voice** preference defaults to Pocket TTS and applies across sections and repositories. Saved per-section text/pronunciation edits survive; legacy cloud preferences never override that global choice. Existing Google preferences and cache keys retain their provider identity; changing engines does not relabel previous recordings. The local disclosure is `pocket-narration-2026-10-15-v1`. The source pins Pocket TTS 3.3.0, Python 3.13.14, the English September 2026 model configuration and immutable Alba embedding. Full asset revisions and runtime dependencies are recorded in [Pocket runtime](research/pocket-tts-runtime.md).

Explicit setup downloads the app-managed `uv` 0.13.4 tool, interpreter/dependencies and public fixed model/voice assets into app data. The present target is Apple Silicon macOS; you do not need a separate Python or `uv` installation. It is not a bundled offline runtime. Setup has no narration script. Synthesis uses app-managed local assets in offline mode, with the edited script supplied to a finite worker over stdin; there is no listening server, API key lookup or cloud fallback. The pinned tool archive is SHA-256 verified before extraction. Fresh packaged setup, offline, cancellation and packaging claims still require execution evidence.

Local synthesis has no provider usage fee. Pocket code/model licensing and voice attribution are distinct: the implementation records MIT for Pocket code/model and Alba MacKenna's source recording under CC BY 4.0. The app-managed `uv` setup utility is dual-licensed MIT OR Apache-2.0; both upstream notices are included in the Mac app resources. Distribution must retain required notices and qualify the complete packaged dependency inventory. Alba is the only offered voice; delivery-style prompting and arbitrary voice/model URLs are unsupported.

Native review validates the exact pronunciation-expanded text and deterministic segments, up to 16,000 UTF-8 bytes per section and 4,000 bytes per segment. Local captions show the resolved text; runtime and delivery configuration stay in Connections. A finite worker owns one reviewed script and loads the model once for that script. Newly published narration units begin local prewarming in the background when Pocket is the selected voice connection; Play stays manual. Only fully completed, validated PCM16 mono 24 kHz WAV sections enter the cache. The local key includes the runtime fingerprint, pinned model/voice, text, segmentation/joining policy and format. A user can read while audio warms; if it is still being prepared at Play, the player waits on that same work rather than creating a duplicate worker request. Export only reads a matching cache and never starts synthesis. Human listening, lifecycle and offline export acceptance remain open.

### Explicit Gemini speech option

Narration has a separate record: `gemini-tts-disclosure-2026-10-13-v2`, checked 13 October 2026. The source currently selects model ID `gemini-3.8-flash-lite-tts` (displayed as Gemini 3.8 Flash-Lite TTS) and the listed prebuilt voices. These are static app values, not a live capability check.

The exact outbound narration request(s) contain one selected section's edited speech text after any explicitly enabled pronunciation substitutions, the selected voice, delivery style, and WAV response format. Scripts up to 16,000 UTF-8 bytes are split into sequential segments of at most 4,000 bytes, preferring sentence boundaries and otherwise whole-word boundaries; the request review shows the full text and each exact segment. Source files, citations, file paths, and the whole chapter are not included by default. The review is fingerprinted and expires after fifteen minutes. The user confirms the request and current terms before synthesis. A cache hit can be served locally after review without sending another provider request.

As checked in the source disclosure, Google lists this model's standard text and audio output as free on the Free Tier subject to project quota and availability. Code Atlas cannot inspect the key's project tier or remaining quota. The source disclosure lists paid-project rates of `$0.50` per million input text tokens and `$6.00` per million output audio tokens through 31 December 2026 (`$0.0015` per 10 seconds), then `$1.00` and `$12.00` from 1 January 2027. These prices and future rates must be rechecked against Google's pricing page before any release after the check date. A Free Tier label does not establish that a particular request is free or available.

Gemini narration has its own Google data-use, regional, eligibility, and billing disclosure. The OpenAI and Anthropic text API disclosures do not apply to this speech request. For Paid Services, the shipped notice describes Google's stated product-improvement and limited logging terms. The app cannot inspect the key's billing project, region, age, or eligibility. The request is sent directly to Google's Gemini API over HTTPS, without a retry or paid/model fallback; local cancellation cannot establish whether Google received a request already in flight. The transcript and previous cached audio remain available on error.

Speech review/cache and both backend disclosures are defined in `src-tauri/src/narration.rs`; the local worker is managed by `src-tauri/src/pocket_tts.rs`. Text-generation disclosures are defined in `src-tauri/src/provider.rs`, and Codex account lifecycle in `src-tauri/src/codex_agent.rs`. The dates and terms in this document are release metadata and must be reviewed before distribution.
