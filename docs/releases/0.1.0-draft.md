# Code Atlas 0.1.0 — release readiness draft

**Status:** unreleased, as of 29 October 2026. This is a planning draft, not a
download announcement. No release target date is recorded. The `0.1.0` values in
the package manifests identify the current source version; they do not mean a
release has shipped.

## Intended first-release scope

The proposed first release is a Codex-first Mac app for understanding a local
repository. A reader should be able to capture a bounded immutable snapshot,
ask about its implementation, follow a visual explanation to exact captured
source, inspect files and local Git changes, and save or revise explanations.
The local app should remain useful for browsing when no model connection is
available. This scope has not yet been frozen.

## What the current source implements

- A Tauri Mac app with a persistent Explorer, Search, Changes and Explorations
  workspace. Guide, Flow and chat history belong to the current exploration.
- Local repository inventory and immutable source snapshots. Capture is limited
  to 2 MiB per file, 100 MiB and 25,000 paths per snapshot, 1,024 UTF-8 bytes
  per path, and 1,000 directory entries per directory. It excludes `.git`
  contents, nested repositories, symlinks and configured generated/cache paths.
- A static syntax index with bounded structural support for Rust, TypeScript,
  TSX, JavaScript, Python and Go. It is not a complete runtime call graph or a
  claim that every language is fully understood. The [language capability
  matrix](../LANGUAGE_CAPABILITIES.md) defines the current limits.
- A Codex account route for workspace questions and a growing set of chapter,
  source-range, plan and Git explanation operations. Source adapters exist for
  more operations than have been qualified in the packaged app. Account,
  operation, cancellation, recovery, large-repository and explanation-quality
  acceptance remain open.
- Optional, reviewed direct API routes for selected operations. They use
  provider-specific keys held in macOS Keychain; the app does not silently
  switch providers or models.
- Chapter review and revision history, app-rendered source-linked visuals,
  manual section navigation, and optional Pocket TTS narration. Visuals use a
  constrained app-owned format; model-supplied HTML or scripts are not run.

These are source capabilities, not proof that the product is ready to ship.
The sample [workspace preview](../../workspace-preview.html) uses illustrative
answers and does not prove native behavior or generated-answer quality.

## Limits to state to early users

- Repository capture and the structural index are bounded; large files,
  unsupported syntax and omitted paths may not be available to an explanation.
- A cited range proves where text came from, not that a generated explanation
  is semantically correct. Real-repository narratives, visuals, listening
  quality and human comprehension still need review.
- The Codex account route may use account quota. The app cannot determine a
  user's entitlement, quota, eligibility or remaining allowance. Direct API
  model names and terms are static metadata and must be rechecked against
  first-party sources before release.
- Pocket setup downloads its managed runtime and English model/voice assets.
  It requires internet during setup and sufficient local disk space and memory.
  Clean-account install, audio quality, cancellation and offline export remain
  unqualified.
- Offline HTML export is a reader copy, not an app backup or restore format.
- macOS 14.0 is declared as the packaging floor. Apple Silicon is the only
  recorded Pocket runtime qualification; other architectures and clean-account
  compatibility have not been established.

## Release gates

Before calling 0.1.0 a public Mac release, the owner still needs to:

1. Freeze the first-release scope and finish its open P0 product requirements,
   including Chapter Studio, coherent repository explanations, useful
   source-grounded visuals and packaged workspace parity.
2. Qualify the end-to-end workflow in the packaged app on representative
   repositories, including source navigation, nested exploration, saved work,
   interruption/recovery and selective edits. Human review must confirm the
   explanations and narration are useful; passing schemas or tests alone is
   insufficient.
3. Complete keyboard, VoiceOver, contrast, zoom/reflow and reduced-motion
   review, plus clean-account installation, local browsing, Keychain and
   storage-recovery checks.
4. Recheck provider disclosures, model availability and terms immediately
   before distribution.
5. Produce and inspect a signed, notarized artifact on a clean supported Mac,
   record its revision and checksums, and publish accurate release notes.

The repository records an unsigned `.app`/`.dmg` packaging preflight. That is
not a user download, a signature, notarization, a clean-account install, or a
release. See [macOS packaging](../kata-tasks/25-macos-packaging.md), the
[distribution license record](../kata-tasks/77-distribution-license.md), and
the live [Kata backlog](../KATA_BACKLOG.md) for evidence and remaining work.
