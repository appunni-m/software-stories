## Failure and change

The [preserved ordinary Fontdone result](2026-10-17-shared-chapter-scenes.md#teaching-policy-follow-up-rejected-layout)
has five composition children whose parents are content cards. Native admission
correctly rejects the draft, but the previous lexical preflight reports no
finding and never offers the existing correction opportunity. A regression
against that unchanged artifact first failed with zero findings versus five.

Current ordinary Codex file, overview, planned-file and selected-section chapter
reviews use `chapter-layout-and-identifiers-v2`, with `maxAttempts:1`. The policy
is part of the reviewed request, including requests without a question. Strict
policy decoding and review reconstruction reject changed configuration. Legacy
retrieval retains its original identifier policy and exact wire identities;
progressive answers keep their existing bounded proposal mechanism.

The composition validator and new preflight share the same tree rules. Feedback
contains only field positions and fixed codes for parent, count, depth,
empty-group and layout-content failures. It is bounded to 64 findings; oversized
input is not traversed, and unknown/future shapes remain the full validator's
concern. Source values, labels, paths and excerpts are not copied into tree
feedback. Full source and semantic validation are not replaced by preflight.

The worker makes at most one correction in its original ephemeral thread with
the same source, schema, model, effort, permissions, cancellation owner and
deadline. It asks for the whole corrected candidate. No production path patches
indices, drops claims, fetches more files or starts a new generation to make a
candidate pass. Persistent findings fail; full independent admission still
checks the returned candidate before any draft can be published.

not perform that transformation.

A separate explicit installed-account test used **GPT-6 Luna/max** and a tiny
TypeScript function. Its first-turn instruction deliberately supplies an invalid

the first raw model response, so only the supplied initial fixture, correction
event and final response are retained. It does not prove byte identity of that
first response, a natural Fontdone repair, ordinary visual quality, native UI
behavior or human comprehension/listening. Nothing was accepted into user
history.
