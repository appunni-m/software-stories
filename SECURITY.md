# Security reporting

This project does not publish a verified private security-reporting address or intake route. It also does not state a response time or supported version policy. Do not post credentials, private source, or details of an unpublished vulnerability in a [public GitHub issue](https://github.com/appunni-m/software-stories/issues) or discussion; the public issue tracker is not a confidential reporting channel.

Until the project owner publishes a monitored private reporting route, its scope, response expectations, and supported-version policy, this repository cannot route a confidential vulnerability report.

The app is under development. The provider and data-flow boundaries described in [Provider disclosures](docs/PROVIDER_DISCLOSURES.md) and the [technical plan](docs/TECHNICAL_PLAN.md) are source-level documentation, not a security certification or a promise that every release gate has passed.

The current local input boundaries, limits, adversarial test coverage, and unsupported package-import scope are recorded in [Security validation](docs/SECURITY_VALIDATION.md). That inventory describes implementation and test evidence; it is not a security audit.
